# Security Architecture & RBAC Security Matrix

## 1. Role Definitions & Permission Boundaries

The application defines three rigid roles with zero privilege escalation paths:

| Dimension | Role 1: Customer | Role 2: Admin | Role 3: Platform Super Owner |
| :--- | :--- | :--- | :--- |
| **Target User** | Prospective homebuyer or tenant | Real estate agent / operations lead | Platform owner / lead compliance officer |
| **Authentication** | Password or Phone OTP (Optional Web Portal) | JWT with Argon2id Password Hashing | JWT with Argon2id + Elevated MFA Token |
| **Voice Interface** | **Full Access**: Real-time microphone audio | No access | Testing & system evaluation mode |
| **Conversation Priority Table** | Denied | **Read-Only / Manage**: Triage leads, priority rank | **Full Access** |
| **Total Customer Details Table** | Denied (Access only to self profile) | **Read / Update**: Customer CRM contact info | **Full Access** |
| **Raw Conversation Transcripts** | **Strictly Forbidden** | **Strictly Forbidden** (Pruned at DB & API) | **Allowed** (Audited read logging) |
| **Raw Audio Playback** | **Strictly Forbidden** | **Strictly Forbidden** (Pruned at DB & API) | **Allowed** (Audited stream logging) |
| **Dataset Ingestion & Rollback**| Denied | View Ingestion Status Only | **Upload, Map, Confirm, Ingest, Rollback** |
| **Audit Log Viewing** | Denied | Denied | **Read-Only Immutable Log Inspection** |

## 2. Transcript & Audio Isolation Enforcement (Dual-Layer Defense)

### 2.1 API-Level Isolation
- **Route Guards**:
  - FastAPI dependency `require_role(["super_owner"])` is enforced on all endpoints serving conversation transcripts (`GET /api/v1/super-owner/conversations/{id}/transcript`) or audio streams (`GET /api/v1/super-owner/conversations/{id}/audio`).
  - The Admin endpoint (`GET /api/v1/admin/conversations`) serializes records exclusively using `AdminConversationSummaryResponse`:
    ```python
    class AdminConversationSummaryResponse(BaseModel):
        id: UUID
        customer_id: UUID
        session_id: str
        duration_seconds: int
        conversation_priority: str
        created_at: datetime
        # CRITICAL: encrypted_transcript and audio_storage_path are omitted from this schema
    ```
- **SQL Projection Pruning**:
  - The SQL query backing Admin endpoints explicitly projects only non-sensitive columns (`SELECT id, customer_id, session_id, duration_seconds, conversation_priority, created_at FROM conversations`). The encrypted text and audio reference columns are never selected into backend memory for Admin requests.

### 2.2 Database-Level Encryption & Isolation
- **Encryption at Rest**:
  - All transcripts are encrypted in the application layer prior to insertion using authenticated symmetric encryption (AES-256-GCM via cryptography / Fernet).
  - The column `conversations.encrypted_transcript` holds raw ciphertext and nonce.
  - The decryption key is injected strictly at the application process boundary via `ENCRYPTION_MASTER_KEY` and is never persisted in SQL or exposed to database reporting accounts.
- **Audio Storage Protection**:
  - Raw audio files are stored in a private directory or S3 bucket inaccessible to public traffic.
  - Access is mediated exclusively by Super Owner endpoints generating time-limited signed URLs (TTL $\le 60$ seconds) following audit log verification.

## 3. Audit Logging Specification

### 3.1 Tamper-Evident Immutable Log
Every action involving sensitive data triggers a synchronous insert into `audit_logs` within the same database transaction:
- **Logged Events**:
  - `READ_CONVERSATION_TRANSCRIPT`
  - `STREAM_CONVERSATION_AUDIO`
  - `INGESTION_DATASET_UPLOAD`
  - `INGESTION_CONFIRM_MAPPING`
  - `INGESTION_EXECUTE_ROLLBACK`
  - `UPDATE_CUSTOMER_PROFILE`
- **Data Attributes Recorded**:
  - `user_id`: UUID of the authenticated actor.
  - `user_role`: Role at execution time.
  - `action`: Specific uppercase action enum.
  - `resource_type`: e.g., `'conversation'`, `'ingestion_batch'`, `'customer'`.
  - `resource_id`: Target entity primary key.
  - `ip_address`: Client IP address from request headers.
  - `user_agent`: Client browser/device string.
  - `timestamp`: UTC timestamp generated by PostgreSQL `NOW()`.

## 4. Password Hashing & Secrets Management
- **Password Hashing**: Implemented using `Argon2id` (RFC 9106) via `passlib[argon2]`.
- **Environment Isolation**:
  - `.env` files never committed to version control.
  - Development defaults (`USE_MOCK_VOICE=true`) ensure no AWS credentials, secret keys, or cloud infrastructure are required to run tests or local development.
